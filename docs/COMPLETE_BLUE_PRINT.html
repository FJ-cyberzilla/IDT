IDT (Intelligent DNS Tool) — Complete Technical Blueprint

This technical blueprint provides an exhaustive architectural overview of IDT (Intelligent DNS Tool), detailing the multi-layered Go backend, Bubble Tea terminal user interface (TUI), Guardcat resilience watchdog, Vault instrumentation pipeline, and network diagnostic engines.

1. Architectural Overview & Component Topology

IDT is structured around strict separation of concerns, zero circular dependencies, and absolute concurrency safety. The system is partitioned into five primary tiers:

CLI & TUI Layer

Powered by Cobra (`internal/cmd`) and Bubble Tea (`internal/ui`) with Lip Gloss styling for real-time telemetry redraws.

Network & Dialer Layer

Unified dialer abstraction (`internal/dialer`) supporting DoH (RFC 8484), DoT (RFC 7858) with DPI fragmentation, and Standard UDP/TCP.

Vault & Live Pool

Dynamic resolver pool manager (`internal/vault`) handling seed candidate loading, warm-up probing, oracle baselining, and JSONL logging.

Guardcat Watchdog

Resilience and memory sentinel (`internal/guardcat`) enforcing endpoint health lifecycle, circuit breaking, and GC watermarking.

2. Core Subsystem Specifications

2.1 Network Resiliency & DPI Bypass (`internal/dialer/dot.go`)

IDT implements advanced TLS ClientHello 1-byte fragmentation and `TCP_NODELAY` wrapping (`dpiFragConn`) to bypass Deep Packet Inspection (DPI) SNI filtering without increasing handshake latency (optimized to 2ms delay).

2.2 Error Recovery & Android Private DNS (`internal/errorhandling`)

Diagnoses Android Private DNS stubs and VPN disconnected states (`IsAndroidPrivateDNSFailure`), automatically recovering via secure encrypted TCP bootstrap lookup against trusted public recursive resolvers (`1.1.1.1:53`).

2.3 Guardcat Health Watchdog (`internal/guardcat`)

Monitors consecutive failures and EOF/reset drops, enforcing circuit breaking (`HEALTHY` ➔ `DEGRADED` ➔ `UNHEALTHY`) and automated garbage collection under memory pressure.
